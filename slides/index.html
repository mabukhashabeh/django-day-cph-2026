Staging is not a personality test.

A manage.py check failure reached staging because one machine had the hook, and another did not.

What pre-commit actually runs

1
Hooks see staged files. Not the working tree. Forget git add, commit the old bug.
2
exclude: is a regex, not gitignore. ^/migrations/ matches almost nothing in an app folder.
3
types: [python] on whitespace means templates and YAML are never checked.

This looks careful. It is a no-op.

# does not match apps/billing/migrations/0007.py
exclude: "^/migrations/"

# does
exclude: "migrations/"

Order is the product.

  1. Hygiene — secrets, breakpoint(), merge markers
  2. pyupgrade → autoflake → isort --profile black → black
  3. flake8 → bandit → mypy
  4. Django: check, then makemigrations --check

Hygiene that fires

debug-statements catches last night’s breakpoint().
detect-private-key catches PEM headers.

It does not catch

AWS keys, GitHub PATs, a Django SECRET_KEY in settings. That needs detect-secrets, gitleaks, or a regex. Say this to your team.

Excludes are not cheating.

mypy on Django migrations will fail a legacy tree and get the hook deleted. Tests are allowed to assert — skip bandit B101.

A 140k-line tree does not get religion on Monday.

  1. Hygiene only. One PR.
  2. black + isort on one app, or only in CI via --all-files.
  3. Then flake8. Then mypy. Then Django checks.

The Django part

- repo: local
  hooks:
    - id: django-system-check
      entry: python manage.py check
      language: python
      additional_dependencies: ["django>=5.1"]
      pass_filenames: false
      always_run: true

Two more things people miss

Without pass_filenames: false, Git paths get appended. manage.py check views.py is not a command. The hook gets removed.
Custom checks in checks.py do nothing until AppConfig.ready() imports them.

How a bad commit still “passes” on a machine

1 Nobody ran pre-commit install. New clone. New hire. The yaml sits in git and does nothing.
2 git commit --no-verify — the hook file is skipped for this one commit.
3 SKIP=debug-statements git commit — one hook silenced, the rest look green.

The machine is not the repo.

Local hooks are advisory. Make this check required on the branch. Not optional. Not “we’ll look at the red X”.

# .github/workflows/pre-commit.yml
- uses: actions/setup-python@v5
- run: pip install -r requirements.txt
- uses: pre-commit/action@v3.0.1

Local hooks protect the people who installed them.

CI protects the repo.

When this is the wrong tool.

The test suite. Coverage. A missing GitHub secret. Anything that needs a database or the network — that is CI config, not a commit hook.
mypy on the whole tree, every commit — pre-push or CI.
Ten hooks on Monday in a 140k-line repo.
The machine as the only gate. detect-private-key as a secrets program.

optional · two minutes · no vendors

One rule about AI review

Deterministic checks can block a commit. Probabilistic reviewers can only advise.

Models are fluent. They are not embarrassed. You need more gates, not fewer.
